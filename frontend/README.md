# سنا | SANA — React Frontend

واجهة أولية تفاعلية مبنية باستخدام React + Vite، مع هوية سنا الأصلية، عربي RTL / English LTR، ورسوم CSS/SVG خفيفة.

## التشغيل لأول مرة (Windows / IntelliJ / VS Code)

1. ثبّتي Node.js (نسخة حديثة، ويفضّل Node.js 20.19+ أو 22.12+).
2. افتحي Terminal داخل مجلد `SANA-master/frontend`؛ **لا تشغّلي هذه الأوامر من مجلد الـ Spring Boot الرئيسي**.
3. اكتبي:

```bash
npm install
npm run dev
```

4. افتحي `http://localhost:5173`.

**ما تحتاجين تشغّلين Spring Boot الآن.** الواجهة تعمل افتراضيًا بوضع Demo وتحفظ بياناتها في `localStorage` داخل متصفحك فقط. احفظي نسخة احتياطية للمشاريع المهمة بزر **Export JSON**. هذا التخزين ليس حساب مستخدم ولا مزامنة سحابية.

لإنشاء نسخة نشر تجريبية:

```bash
npm run build
npm run preview
```

## وش شغال الآن؟

- الصفحة الرئيسية، صفحة المشاريع، المكتبة، صفحة الأدوات، واستوديو المشروع.
- إنشاء المشاريع وتعديلها وحذفها، وإنشاء الشخصيات والعوالم والأماكن والقوانين والأحداث وتعديلها وحذفها.
- خريطة العلاقات: سحب العقد، تكبير/تصغير، فلترة، علاقات ملونة مسماة، إنشاء الروابط، وفتح عنصر للتحرير.
- العربية والإنجليزية مع ضبط اتجاه الواجهة تلقائيًا (RTL/LTR).
- تصميم متجاوب للجوال والكمبيوتر، وحركات انتقال خفيفة، ودعم نظام تقليل الحركة (`prefers-reduced-motion`).
- حفظ محلي تلقائي في Demo، وتصدير/استيراد مشاريع بصيغة JSON.

**غير متصل بعد:** تسجيل الدخول الحقيقي، Spring Security، مساعد الذكاء الاصطناعي، n8n، Google Docs، وبقية تكاملات اللعبة المتقدمة. يظهر المساعد كواجهة تعريفية فقط؛ لا تُرسل الرسائل لخادم AI. لا توجد «مصادقة وهمية» أو كلمات مرور مخزنة.

## الربط التجريبي مع Spring Boot لاحقًا

يوجد Client أولي للـ REST APIs في `src/lib/data.js`، مع عزل واجهة React عن طبقة البيانات. ربطه بالخادم **تجريبي ولم يُختبر تشغيليًا على قاعدة بيانات حقيقية**. لا تفعّلي هذا الوضع قبل مراجعة صلاحيات الـ endpoints وإصلاح الـ Backend اللازم.

1. أنشئي ملف `.env` بجانب `package.json`:

```env
VITE_SANA_MODE=api
```

2. شغّلي Spring Boot محليًا على `localhost:8080`. يحتوي `vite.config.js` على proxy يحوّل `/api` إلى الباك إند لتجنب مشكلات CORS أثناء التطوير.
3. لا تكتبي API secrets في متغيرات `VITE_` أبدًا؛ أي قيمة فيها تكون مرئية داخل الفرونت إند.
4. **تسجيل الدخول:** الباك إند محمي بـ HTTP Basic. تظهر شاشة الدخول أولًا (البريد الإلكتروني وكلمة المرور، أو إنشاء حساب)، وتُرسَل بيانات الدخول مع كل طلب وتُحفظ في `sessionStorage` فقط حتى إغلاق التبويب. كل مستخدم يصل إلى مشاريعه فقط.

عند تغيير `.env` أوقفي `npm run dev` وشغّليه من جديد.

### ملاحظات عند تشغيل API mode

- بعض الـ Controllers تعيد `ApiResponse` بدل العنصر الجديد. يعتمد الـ Client مبدئيًا على إعادة قراءة القوائم بعد الإنشاء.
- عناصر الخريطة تُربط بهوية `ProjectNode` في Spring Boot، لكن بواجهتها الخاصة تستعمل `entity.id`؛ يُترجَم معرّف العقدة أثناء تحميل العلاقات.
- قد يتطلب `ProjectOutput` وJPA relations وDTO validations تغييرات إضافية قبل الربط الكامل، خاصة مع المصادقة وحقول الشخصيات المطلوبة.
- يرجى التأكد من أن العلاقات/البيانات تخص مشروع المستخدم، وعدم الاعتماد على `userId` المرسَل من الواجهة كوسيلة أمان.

### الربط الحالي مع الباك إند (أكتوبر 2026)

- **المجالات:** الكتابة والألعاب = `CREATIVITY`، البرمجة = `TECH`، التجارة = `BUSINESS`، وأُضيف مجال **تعليمي** = `EDUCATION`.
- **المخططات:** كل مشروع يمكن أن يحتوي أكثر من مخطط (معمارية، ERD، Class، Use Case، نماذج الأعمال، خريطة ذهنية، خريطة القصة...). اختاري المخطط من أعلى الخريطة أو أنشئي مخططًا جديدًا. أنواع العقد تأتي من `GET /api/v1/diagram/types`.
- **التعديل اليدوي:** المخططات غير الإبداعية تُحفظ عبر `/api/v1/diagram` مع `expectedRevision`، والعناصر الإبداعية عبر endpoints الشخصيات والعوالم كما كانت.
- **مساعد سنا الذكي:** يعمل داخل المشروع (نصيحة، تعديل المخطط، إنشاء مخطط جديد). أي تغيير يظهر كاقتراح ولا يُحفظ إلا بعد الضغط على «قبول».
- **شجرة الحوارات وتوازن الشخصيات:** تستخدم مخطط `BRANCHING_STORY` وخريطة القصة، وتُنشأ تلقائيًا عند الحاجة.
- **لوحة الإلهام:** محفوظة في المتصفح فقط لأن الباك إند لا يحتوي API لها بعد.

## React للمبتدئين (شرح سريع)

- **Component:** جزء قابل لإعادة الاستخدام من الواجهة، مثل `ProjectCard` أو `Studio` أو `MapView`.
- **JSX:** نكتب عناصر تشبه HTML داخل ملفات `.jsx` ونربطها ببيانات JavaScript.
- **State / `useState`:** ذاكرة مؤقتة للواجهة (مثل اللغة، نوع النموذج المفتوح، أو مربع البحث).
- **Props:** مدخلات ترسلها صفحة لمكوّن آخر (مثل `project` أو `onSave`).
- **`useEffect`:** ينفذ فعلًا جانبيًا عند التحميل أو تغيّر قيمة (مثل تحديث لغة الصفحة أو تحميل مشروع).
- **Repository:** طبقة `data.js` هي التي تقرر أين تحفظ البيانات. تبديل Backend لا يتطلب نسخ طلبات `fetch` في كل زر.
- **CSS animations:** معظم الحركة باستخدام `transform`, `opacity` أو تحولات بسيطة؛ تم تجنب المؤثرات الثقيلة أو مكتبات التحريك الكبيرة.

نصيحة: ابدئي من `src/App.jsx` وابحثي عن `function Landing` ثم `function Studio`، بعدها افتحي `src/lib/data.js` لتعرفي أين تحفظ عملية إنشاء المشروع.

> تنبيه: هذا إصدار Frontend قابل للتطوير، وليس منتجًا مكتملًا أو جاهزًا لنشر بيانات حقيقية. يوجد باك إند مرفق كما رُفع، دون تعديلات عليه.
